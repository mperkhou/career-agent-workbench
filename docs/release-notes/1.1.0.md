# Career Agent Workbench 1.1.0

Status: release candidate pending G04 and merge/tag approval.

This release is restoring the private operational workflows required to use
the public application code with an operator-owned external workspace. The
current P01 slice adds a two-phase bootstrap/private dotenv boundary with
deterministic precedence, fail-closed path and permission checks, and no
global-environment mutation. It also restores workflow-specific JOD,
core-skill, second-pass, manual-pass, and highlighting model selection, with
GLM workflow defaults and `gpt-5.6-sol`/`high` highlighting routing while the
general API model remains unchanged.

The current slice also restores the non-UI operational CLI and Make behavior:
first-draft replacement remains explicitly conditional; JOD apply creates a
SQLite backup by default and refreshes ATS fields unless opted out; bounded
query outcomes are persisted and reused; highlighting can target a company or
job order with a bounded span limit; and callers can select a private template
and explicitly export rendered YAML, HTML, and PDF beneath the private
workspace. Pass one can emit only its prompt to stdout or an explicit private
file, while raw model-response persistence remains disabled.

P01 also adds reusable guarded support for creating a new private workspace,
copying only explicitly selected members without following links, taking an
online SQLite backup, and running application initialization only against a
second disposable copy. Comparisons expose counts and invariant booleans for
schema compatibility, rows, selection/lineage, JOD/ARO/CLO presence, and
artifact equality; failures leave the source and retained copy unchanged.

The JOD audit now uses the application state layer's exported result bound, so
the direct command and Make wrapper remain compatible with real tracker state.
The manual pass now sends rendered skill categories through the same single
patch request and evidence boundary as its other targets. Its prompt requires
continued pruning and de-duplication while preserving supported DevOps,
scalability, CI/CD, cloud, and GitHub Actions terms, and rejects unsupported
surrounding claims without imposing a deterministic term-list validator.

Copied-state validation now recognizes the initializer's one bounded legacy
normalization: a non-empty automatic selection with no matching source variant
may become empty. The comparison still requires exact preservation of every
valid automatic selection, explicit manual selection, variant and lineage
invariant, application artifact count, and artifact digest, and reports only
the number of normalized pointers.

Artifact comparison now follows the application's established source of truth:
every DB-backed resume variant is compared byte-for-byte, application-level
resume artifacts remain canonical only where no variant exists, and resume
backups plus cover-letter objects and content are always compared. A stale
application projection may therefore be resynchronized from its unchanged
selected variant without hiding any canonical artifact change.

P02 restores the modular single-user tracker surface: allowlisted search,
status/scope filters, deterministic sorting, preserved local view state, and
explicit status, archive, restore, and confirmed-delete mutations over the
existing state API. The Add page can run the configured matching Make target
in the app-scoped background registry or atomically seed public LinkedIn and
generic URL details through the existing guest provider and parser boundaries.
The seven established Make actions remain allowlisted, with bounded sequential
v1/v2/manual/highlighting composition, stage/count-only polling, and explicit
ATS recalculation against the selected resume projection without page-load
writes or selection changes.

P03 restores the local document workbench without restoring the legacy Flask
monolith. Selected and exact v1/v2/manual resume HTML and PDF artifacts can be
viewed or downloaded directly, variants can be compared and explicitly selected
or reset to automatic preference, and an explicit configured private download
directory accepts only guarded resume or cover-letter PDF copies. The JOD page
preserves source and prompt text while refreshing only the active ATS projection.
The active resume editor round-trips complete YAML and uses an opaque revision
token for atomic render, ATS, one-level target-bound revert, and deterministic
sync operations. Cover-letter edits are sanitized to a small inert formatting
allowlist, normalized to plain text, and rendered to a stored PDF atomically.

P04 completes the local operator contract. `make install` creates the public
`.venv`, installs the editable development/browser extras, and installs
Playwright Chromium explicitly. All Make workflows resolve through that public
environment. PID/log-backed website start, stop, and restart own only the exact
recorded child, remove stale state safely, and open a browser only when the
operator opts in. The repository ships exactly five rewritten public skills,
and the canonical MCP registration resolves to the public
`career-agent-workbench-mcp` executable while the legacy registration remains a
temporary fallback through G04.

The source distribution now lists every restored P02/P03/P04 module, template,
static asset, focused test, operator script, and skill asset explicitly. The
wheel keeps recursive package resources, all six console entry points, and the
installed module/resource smoke contract. Release readiness requires one
complete synthetic gate from the public environment plus a fresh
disposable-first private snapshot validation before retained-ops promotion.

Real profile data, application state, generated artifacts, credentials,
machine-specific configuration, migration backups, and cutover evidence remain
outside the public repository. Merge, tag, release, deployment, and external
career actions remain separately gated.
