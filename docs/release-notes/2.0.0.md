# Career Agent Workbench 2.0.0

Status: the exact archive-first source import, activation, and public database
compatibility phases are complete. The archived 31-route application is the
console/operator Flask implementation through a thin public runtime boundary;
integrated 2.0.0 release-readiness validation remains gated by the committed
P/G plan.

This major release replaces the reconstructed 1.1/1.2 Flask user interface
with the mature application from the archived LinkedIn Career MCP codebase.
The archived application is the behavioral, route, and visual source of truth.
Public-workspace configuration, database compatibility, packaging, and safety
are adapted around that source rather than used as a basis for redesigning it.

The initial source is one tracked, clean Python module containing the Flask
routes and inline HTML, CSS, and JavaScript. It is bound to an exact repository
commit, tree, Git blob, and SHA-256 in the committed workflow plan. The first
implementation slice copies that source exactly before any activation or
compatibility change.

That exact source is now stored as
`career_agent_workbench._archived_flask_source`. It is deliberately not
imported by the package or wired to the console/operator entrypoint yet. A
focused test originally bound its SHA-256 and line count. After that exact
normal commit, activation changed only package/API and runtime boundaries; the
seven inline HTML/CSS/JavaScript and browser-launcher literals remain bound to
their original hashes. Ruff lint still covers the imported source, while Ruff
formatting excludes that one file so its archived presentation is not silently
rewritten.

The `career-agent-workbench-webapp` console script and PID-owned website
operator now launch the archived application. The adapter resolves the central
external workspace once, supplies the exact database, output, configured
downloads, packaged resume template, and project root, and propagates only
allowlisted workspace paths to background Make commands. The archived app no
longer defaults artifact cleanup or copying to the real home Downloads folder.
Its generic-job fetch path uses the public bounded transport/parser boundary,
and the renamed public base exception is mapped without changing UI behavior.

Initial offline Chromium validation served the archived tracker and Add pages
with the expected one-row table, Actions control, and Seed/LinkedIn/Other forms
from a fresh fictional workspace, with zero external browser requests. The
compatibility boundary now initializes only an uninitialized schema before app
creation; ordinary app creation and GET requests leave an already initialized
database byte-identical. Archived resume edits, reverts, selection, status,
archive, deletion, JOD/ATS, and CLO writes use the canonical public state
contract so selected variants, active projections, backups, and opaque
revisions remain coherent.

The inactive reconstructed 1.1/1.2 templates, JavaScript, and split Flask UI
modules have been removed after reference tracing. The reusable bounded
generic-ingestion service remains, and `career_agent_workbench.webapp` is a
small compatibility import for the archive-first runtime rather than an
alternate frontend.

Private profile files, application rows, databases, credentials, generated
career artifacts, machine-specific paths, and private environment values are
not migration inputs and must remain outside Git. Validation uses fictional
workspaces and disposable database copies. Provider calls, authenticated
LinkedIn access, application submission, publication, cutover, and retirement
of the archived fallback remain separately gated.
