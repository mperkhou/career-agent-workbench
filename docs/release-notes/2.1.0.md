# Career Agent Workbench 2.1.0

Status: documentation-parity implementation is in progress. The realistic
fictional resume, derived Master Resume Object, full-size fictional job target,
and README parity pass are complete. The recorded synthetic traversal is paused
before visual work while an approved offline API retry-contract and additive
diagnostic repair proceeds through P03D/G03D.

This documentation-centered release replaces the intentionally compact
fictional resume text and Master Resume Object with a realistic, full-depth
public demo. The approved demo preserves the source profile's technical breadth
and section depth while replacing identifying people, employers, locations,
institutions, projects, credentials, links, chronology, and distinctive
phrasing. One designated long-form role is reduced to roughly half its source
volume; the remaining roles preserve their full substantive depth.

After separate review of the public resume text and its derived MRO, the README
was rebuilt to relative parity with the mature archived documentation. Its
examples come only from the approved fictional demo. Its diagrams and Flask
screenshots remain behind their accuracy, privacy, and synthetic-state review
gates.

Private source content, application state, generated career artifacts,
credentials, machine-specific paths, and content-bearing evidence remain
outside Git. Product behavior changes remain out of scope except the narrowly
approved P03C execution-parity work and P03D typed API-retry and sanitized-
diagnostic repair. P03D keeps one workflow-owned retry budget for API-backed v1
and v2 operations, adds only legacy-compatible failure subtypes to the existing
diagnostic stream, leaves Ollama timeout-only, and does not change manual-pass
or highlighting retries. A generalized direct/Make/Flask durable recorder,
leases, cross-process ownership, restart recovery, multi-run correlation,
truncation aggregation, durable final-summary state, composite-Make ownership,
and a structured viewer are deferred to a future feature release. P03D is
offline-only and does not authorize another provider traversal. Authenticated
browsing, job-posting retrieval, push, PR, merge, tag, and publication remain
outside this work unless separately approved.
