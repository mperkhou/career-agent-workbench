# Career Agent Workbench 1.2.0

Status: all three implementation/reassessment pairs and the bounded
manual-pass compatibility repair are technically complete. G03 accepted the
nine approved capabilities and release-readiness evidence; merge, tag,
publication, operational cutover, and legacy retirement remain separately
gated.

This in-progress release is scoped to the nine approved operational-parity
gaps deferred from 1.1.0. Work is divided into three bounded implementation
and reassessment pairs: workflow execution and variant-review evidence;
tracker information density and structured resume editing; and a practical
cover-letter workbench with compact professional pagination.

## Workflow execution and review

- Add and Seed can compose dependent v1, v2, manual-pass, and highlighting
  stages with dependency validation and survivor-aware execution.
- Progress is bounded, collapsible, dismissible, and retryable without
  repeating completed survivor work unless explicitly requested.
- Selected-draft sync stays within state-store result bounds across the direct
  script, Make target, and Flask action.
- Variant review uses each variant's declared parent and presents bounded ARO,
  ATS, evidence, and metadata findings without raw provider or private values.

## Tracker and resume editing

- Tracker rows provide accessible status treatment, v1/v2/manual availability
  and selection badges, artifact timestamps, bounded long values, and
  preserved search/filter/sort/lifecycle behavior.
- Edit links remain same-tab, while inline resume and cover-letter artifact
  views use safe new-tab behavior. Existing explicit download behavior is
  unchanged.
- The structured resume editor covers routine nested fields and repeated lists
  while losslessly preserving unknown and optional values. Opaque revisions,
  stale-write rejection, ATS refresh timing, revert, sync, selection
  isolation, and the full-YAML recovery surface remain intact.

## Cover-letter workbench and pagination

- The cover-letter editor supports accessible paragraph, line-break, bold,
  italic, safe-link, and unlink operations with synchronized sanitized source,
  recovery, and live preview surfaces.
- Server-side sanitization remains authoritative, and save/render/view/
  download/copy operations retain their transactional and state-isolation
  guarantees.
- The unchanged representative 511-word letter renders as one readable Letter
  page with exact normalized text and bounded geometry.

## Manual-pass compatibility

The bounded compatibility repair preserves v2's Core Technical Skills
taxonomy and inventory during manual pass, limits model changes to
same-category matched items, and makes exact display skills win over aliases
at render time. Private Jenkins aliases and deferred data-repair notes remain
in the external ops workspace and are not packaged or committed.

## Validation and packaging

- The complete synthetic suite passed 1,081 tests after the final package
  membership repair.
- Ruff, formatting, JavaScript syntax, Git whitespace, and public-tree safety
  checks passed.
- Wheel and sdist builds, archive scans, isolated-wheel imports/resources/CLI
  smoke, real offline Chromium rendering, browser-workbench checks, and the
  injected MCP stdio handshake passed.
- A bounded full-ops read-only aggregate confirmed schema, hydration,
  selection, lineage, and cutover compatibility without exposing values or
  changing the retained workspace.
- Browser and legacy comparisons used fresh independent disposable clones,
  made no provider/model/authenticated/application/employer calls, and deleted
  raw or content-bearing evidence after gate review.

Completed G01/G02 comparisons retain their pre-patch evidence binding. P03 and
G03 used a separately sealed post-patch legacy source snapshot, so concurrent
changes in the archived checkout did not rewrite completed gate history. The
snapshot and content-bearing comparison evidence were deleted after G03
technical review; only sanitized hashes, counts, booleans, states, and findings
remain.

The committed workflow preserves the modular public architecture and existing
state, rendering, selection, and human-review foundations. It does not restore
the legacy Flask monolith or authorize provider expansion, authenticated
LinkedIn access, application submission, generalized security/deployment work,
or unrelated feature development.

Known non-blocking considerations are the measured unfiltered large-tracker
latency and a startup-only physical SQLite rewrite observed on disposable
copies; logical state and GET behavior remained exact.

The legacy application remains the operational fallback. This branch is ready
for pull-request review; merge, tag, release, cutover, and legacy retirement
remain separately gated and require explicit user authority.
