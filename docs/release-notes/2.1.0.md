# Career Agent Workbench 2.1.0

Status: released on 2026-08-05 after documentation-parity implementation,
public-synthetic workflow validation, and the complete release-readiness gate.

## Documentation parity

This documentation-centered release replaces the intentionally compact
fictional resume text and Master Resume Object with a realistic, full-depth
public demo. The approved demo preserves technical breadth and section depth
while replacing identifying people, employers, locations, institutions,
projects, credentials, links, chronology, and distinctive phrasing. Its
full-size fictional job target remains a credible but intentionally imperfect
match.

The README now documents the source-resume and MRO relationship, JOD handling,
v1, v2, manual review, highlighting, ATS diagnostics, Flask tracker, Make and
CLI surfaces, configuration precedence, operational limits, and release
boundaries against the coherent Tessa Rowan/Rivermark example. The tracked SVGs
and PNGs remain generic public-synthetic teaching assets; they are not presented
as captured output from the recorded workflow.

## Workflow reliability corrections

The v1 and v2 API workflows retain one workflow-owned retry budget and one
internal API attempt. Their configured timeout is a wall-clock deadline for
each logical attempt, with backoff outside the deadline and at most
`retry_count + 1` provider boundaries. Validated transient HTTP, transport, and
HTTP-200 embedded-provider failures can retry. Permanent or contradictory
embedded errors, malformed provider envelopes, and oversized responses remain
nonretryable. Ollama remains timeout-only, and manual/highlighting retries
remain limited to Codex subprocess timeouts.

The API client's existing tolerant JSON path accepts bare JSON plus supported
Markdown-fenced and prose-wrapped JSON, then canonicalizes it before strict v2
patch parsing. Syntactically malformed generated JSON is retryable within the
same `retry_count + 1` budget. Once JSON parses, invalid patch schema,
application semantics, evidence, or policy remains nonretryable, as do state,
rendering, ATS, artifact, and configuration failures.

The first-draft producer also materializes tuple-bearing ATS diagnostics as
plain JSON lists before its strict application-state write. The state validator
remains strict, and the production-shaped regression preserves scores, terms,
nested values, collection order, automatic selection, and conditional revision
enforcement.

visual review also passed. Release closeout additionally passed wheel and sdist
builds and scans, an isolated wheel installation and CLI/resource smoke, real
offline Chromium rendering, the disposable Flask browser workbench, and the
injected MCP stdio handshake.

## Safety and release boundary

The deterministic `make demo` path remains offline and separate from the
recorded workflow evidence. It does not invent v2/manual variants or ATS
scores. Private source content, application state, credentials, generated
career artifacts, model traffic, logs, and machine-specific paths remain
outside Git.

A generalized direct/Make/Flask durable recorder, leases, cross-process
ownership, restart recovery, multi-run correlation, truncation aggregation,
durable final-summary state, composite-Make ownership, and a structured viewer
remain deferred. Authenticated browsing, application submission, employer
contact, push, PR, merge, tag, and publication are not part of this
documentation update.
