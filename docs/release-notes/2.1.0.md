# Career Agent Workbench 2.1.0

Status: documentation-parity implementation is in progress. The realistic
fictional resume, derived Master Resume Object, full-size fictional job target,
and README parity pass are complete. The offline API retry-contract and
additive diagnostic repair passed G03D. The one post-G03D recorded synthetic
traversal passed preflight and completed its v1 model operations, then stopped
at the first failed stage without storing a live variant. An approved offline
functional repair now addresses that demonstrated state-write blocker, with a
production-shaped real-store regression. The distinct post-G03S P03T
traversal then passed preflight and completed core, JOD, and three experience
operations before its fourth experience operation ended after 439.688 seconds
as a nonretryable HTTP-200 malformed envelope on attempt one of three. It
stored no live v1 or later stage. Offline-only P03U/G03U now addresses the
demonstrated missing wall-clock deadline and embedded-envelope classification
gap; no successful post-fix live output is claimed.

This documentation-centered release replaces the intentionally compact
fictional resume text and Master Resume Object with a realistic, full-depth
public demo. The approved demo preserves the source profile's technical breadth
and section depth while replacing identifying people, employers, locations,
institutions, projects, credentials, links, chronology, and distinctive
phrasing. One designated long-form role is reduced to roughly half its source
volume; the remaining roles preserve their full substantive depth.

After separate review of the public resume text and its derived MRO, the README
was rebuilt to relative parity with the mature archived documentation. Its
examples come only from the approved fictional demo. Its diagrams and Flask
screenshots remain behind their accuracy, privacy, and synthetic-state review
gates.

Private source content, application state, generated career artifacts,
credentials, machine-specific paths, and content-bearing evidence remain
outside Git. Product behavior changes remain out of scope except the narrowly
approved P03C execution-parity work, P03D typed API-retry and sanitized-
diagnostic repair, P03S first-draft ATS-diagnostics serialization fix, and
P03U's bounded v1/v2 per-attempt deadline and HTTP-200 embedded-provider-
envelope repair.
P03D keeps one workflow-owned retry budget for API-backed v1 and v2 operations,
adds only legacy-compatible failure subtypes to the existing diagnostic stream,
leaves Ollama timeout-only, and does not change manual-pass or highlighting
retries. A generalized direct/Make/Flask durable recorder,
leases, cross-process ownership, restart recovery, multi-run correlation,
truncation aggregation, durable final-summary state, composite-Make ownership,
and a structured viewer are deferred to a future feature release. The consumed
revision-10 P03R authorization permitted only one synthetic
`demo-platform-001` v1 → v2 → regular-manual → highlighting sequence after a
sanitized model-free preflight. It retained two retries/three total attempts per
configured operation and all four external snapshot directories, stopped at
the first failed stage, and did not permit an operator rerun, job retrieval, or
private workspace mutation. Authenticated browsing, push, PR, merge, tag, and
publication remain outside this work unless separately approved.

The revision-10 v1 producer exposed a deterministic state-contract mismatch:
Python tuples retained by `asdict(AtsDiagnostics)` were passed directly to a
JSON-only state validator. P03S now materializes those tuple collections as
plain JSON lists before the first-draft state write. A production-shaped test
uses the real diagnostics dataclass and application store to prove the v1 call
site commits without losing scores, terms, nested values, or collection order;
automatic v1 selection and conditional revision enforcement remain intact. The
repair does not relax the state validator, add logging architecture, access the
retained live workspace, or itself authorize another provider/model/Codex
invocation. The consumed P03T authority permitted only one model-free preflight
and, on successive success, one `demo-platform-001` v1 → v2 → regular-manual →
highlighting sequence at the repaired commit. It stopped during v1 with no
operator rerun, retained the unchanged external workspace and four empty
snapshot directories, and returned to explicit review before P04.

P03U is scoped as a separate offline correction. It will make the configured
v1/v2 timeout a true per-attempt wall-clock deadline rather than only an HTTP
transport-inactivity limit; keep one workflow-owned retry budget and one
internal API attempt; inspect validated top-level and choice-level provider
errors plus `finish_reason=error` before accepting HTTP-200 content; and treat
unusable missing, null, or empty completions as retryable only when no permanent
request failure is present. Permanent or malformed envelopes, oversized
responses, invalid generated JSON, and application/evidence/state failures
will remain nonretryable. Added response diagnostics must be closed, content-
free, optional, and backward compatible with retained category-only and
subtype-only records. P03U does not authorize another synthetic traversal or
the deferred 2.2.0 durable-diagnostics platform; both G03U review and a new
committed plan amendment plus explicit approval are required before any further
live call.
